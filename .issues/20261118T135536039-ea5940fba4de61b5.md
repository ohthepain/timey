## Original request

Give MIDI input subscriptions one owner

Track and release listeners on the previously selected MIDI input when switching devices, clearing the selection, changing channels, reinitializing, or disposing `MidiService`. Preserve current transport and note behavior. The investigation observed that `listenToInput()` replaces `midiInputDevice` before cleanup, so cleanup targets the new device; clearing the selection also returns without detaching listeners ([MidiService.ts:99–114, 180–196]( /Users/paulwilkinson/projects/tanstack-start/timey/.issues/issue-work/20261118T135416986-77a3e85a1ea8b2b3/src/lib/MidiService.ts:180)).

## Why

Stale listeners can remain active after input changes. The report says the prior architecture assessment deferred this candidate and the transport work excluded subscription redesign; no supplied issue title covers it. The separate channel-selection concern was explicitly unverified and is omitted.

## Requested proof

With fake MIDI emitters, switch A→B, clear selection, change channel, initialize repeatedly, and dispose; assert only the selected input delivers notes and clock events. Then check device switching in the browser and, if available, with a physical MIDI device.
