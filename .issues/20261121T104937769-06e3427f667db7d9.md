## Original request

Implement investigation flows and reports

Implement the agreed design in docs/plans/investigation-reports.md. The completed decision map is docs/plans/investigation-reports-wayfinder.md. All five product decisions are settled; this issue is for implementation, not another design interview.

Problem and outcome
Investigations currently have a separate Run investigation page and hardwired follow-up issue creation. Give them the ordinary flow workspace, independently optional report and issue output blocks, and a project Reports tab with retained reports and a full-featured discussion experience.

Flow and run behavior
- Default route: Request → Investigate → Generate report → Create Issues. Include both output blocks by default; either can be removed or run independently from completed investigation findings.
- Output blocks may investigate newer code. Retain their source investigation run, timestamp, inspected revisions, findings, and evidence.
- Create Issues automatically receives additional findings from successful report generation when available, but remains runnable when no report was generated. Failed/stopped attempts stay inspectable and do not automatically forward additional findings.
- Report failure pauses the route; Create Issues remains manually runnable. Separate execution order from input dependencies and invalidation so report presentation edits do not unnecessarily invalidate issue creation.
- Reusable Run again performs a new inquiry on the selected branch followed by the included output blocks and preserves earlier runs. Output-only reruns are attempts under their original investigation run.

Output skills and saving
- Add selectable default skills generate-report and create-issues using existing skill discovery and block selection conventions.
- Each skill chooses how to save its outputs and must return saved-result references and enough source information to attach outputs to the investigation run.
- Reports use rich content in a consistent Timey reader: executive summary, findings, evidence links, recommendations, headings, tables, and diagrams. The skill chooses structure and visual emphasis.
- Create Issues saves actionable uncovered work as Needs approval. Link matching existing issues without modifying them. Approval does not start work.
- Retry after partial issue creation retains successful issues and creates only the remaining work, including with replacement skills. Preserve stable identities and saved outcomes.

Reports and retention
- Add Reports to the project workspace menu. Each successful deliberate generation creates a separate dated report linked to its exact source run and output attempt, even when content is unchanged.
- Retry recovers the same attempted publication without creating a duplicate.
- After skill-owned saving, Timey retains its own report and evidence copies. Published reports remain immutable and readable when originals move, investigations rerun, or investigations are archived.
- If evidence cannot be retained, disappears, or cannot be verified, keep the report readable and clearly mark affected evidence as unavailable/unverified.

Reader and shared chat
- Use the approved C prototype: scripts/factory-ui/report-reading.prototype.html. Full-width reading above optional full-width discussion below. First visits hide discussion; returning restores reading position, discussion visibility, and draft.
- Use a thin resizable divider matching existing sidebars, with the approved hover highlight, a larger invisible grab area, and keyboard resizing. Keep composer controls usable at the minimum split.
- Run selector shows only runs for the current investigation, labeled by run/date, not unrelated reports or report titles. Include All reports and Open investigation navigation.
- Reuse the investigation conversation. New messages receive the selected report as context; earlier messages retain their original report/run context. Omit duplicate context banners and placeholder history.
- Recommended prompts are pills that fill an editable draft without sending.
- Share the message view, composer, styling, and sending behavior across app chats. Use project chat's round arrow send button, user messages on the right, assistant messages on the left, and the same registered skills and tools. Keep conversation histories and ownership separate.
- Apply the standard spoken send command to all chats: a final dictated word go is removed and sends the remaining nonempty prompt; go alone sends nothing; an interior go does not submit. Reuse the existing implementation where available and preserve its behavior.
- Report discussion and explicit follow-up issue requests remain available after source investigation archival without restoring it or starting another investigation run.

Adoption
- Idle standard investigation flows adopt the new layout automatically, preserving settings, history, and approval requirements; loading or migration starts no work.
- Preserve completed inquiries and already-created issues as historical completion. Offer explicit Generate report without repeating inquiry or issue creation.
- Preserve customized layouts until explicit rebuild. Let active runs finish under their existing configuration before adoption.
- Explicitly preserve/map old Understand attempts, attempt IDs, linked issues, partial-creation receipts, and Retry/recovery settings. Failed, stopped, interrupted, or uncertain work never restarts automatically.
- Preserve committed-snapshot inquiry execution, reusable settings, direct archive behavior, and independent follow-up issues.

Verification and delivery
Use the acceptance scenarios in docs/plans/investigation-reports.md. Verify through the real flow, Reports reader, chat, guarded creation, partial failures/retries, archival, and migration using disposable fixtures where appropriate. Maintain affected domain, architecture, codebase, and workflow documentation. Prototype checks are design evidence only; do not report them as production verification. Follow the repository's normal implementation, check, and delivery controls.

Scope exclusions
PDF/other exports are deferred. The prototype is throwaway design evidence, not production code to promote wholesale. Creating this issue does not authorize starting it, running existing investigations, accepting/closing issues, or migrating production records now.

Handoff artifacts

These design/prototype changes are currently local and uncommitted. Preserve them and make the agreed source artifacts available before any isolated implementation launch. The requirements above provide a standalone scope even before that source handoff.
