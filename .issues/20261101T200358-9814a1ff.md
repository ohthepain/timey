## Original request

Add a **Progress** tab beside **Issue output**, **Issue thread**, and **Discussion**.

Progress should be a compact, current-state view derived from the output events:

- **Current step:** “Answering scope questions”
- **What is happening:** “The issue assistant is waiting for your answers before starting implementation.”
- **Completed steps:** concise entries such as “Issue captured,” “Plan approved,” “Implementation started,” “Checks passed.”
- **Next action:** “Answer the grilling questions” or “Continue when the worker finishes.”
- **Status:** running, waiting for you, blocked, failed, or complete.

It should interpret the active operation rather than blindly summarize every log line. For example, when grilling is active, it should show the actual unanswered questions and the answer control. When verification is running, it should show the check currently being executed and a short result. When the UI is stale after Continue, it should immediately replace the old status with “Request sent; waiting for updated progress.”

Keep the full raw stream in **Issue output** for diagnostics. The Progress tab becomes the human-facing explanation of that stream. The **Issue thread** remains the work conversation, and **Discussion** remains conversation about the work.

A good first version would derive a small state machine from existing output events rather than add another independent workflow record. That avoids creating a fourth source of truth.
