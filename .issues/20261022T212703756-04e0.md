## Original request

## Expected behavior

Only explicitly designated users may use application admin privileges, and only those users may see the Admin toggle. The toggle selects an authorized user's admin UI mode; toggling it or modifying local storage must never grant authority. The earlier agreed capability is that admins may modify any beat; broader method/module/account/private-history powers are not implied.

## Current source evidence

Read-only inspection found:

- src/routes/__root.tsx renders the Admin button unconditionally and calls setAdmin(!enableAdmin).
- src/state/PersistedStore.ts stores enableAdmin as a client-controlled persisted boolean.
- src/components/BeatViewer.tsx displays Edit/Copy/Delete controls based on enableAdmin, without checking a designated admin role there.
- No trusted application-admin designation/assignment mechanism was identified in the preceding auth reconnaissance. Existing Keycloak realm roles must not be treated automatically as application admin rights.

This is source evidence; no browser reproduction or forged API request was attempted during capture.

## Acceptance and verification

- Derive admin eligibility from trusted server-side identity/authorization and expose only the necessary eligibility information to the UI.
- Hide the Admin toggle from signed-out users and users who are not designated admins; clear or ignore persisted admin mode on logout/account switching or loss of eligibility.
- Enforce the agreed beat-admin permissions on every relevant server operation. Hiding controls alone is insufficient, and client-supplied roles/IDs or local-storage flags cannot authorize a request.
- Confirm normal owner permissions still work independently of admin mode and preserve unrelated public-read/private-practice contracts.
- Verify designated admin, ordinary signed-in, and signed-out cases, including direct requests, local-storage tampering, account switching, and revocation.
- Resolve the designation/bootstrap mechanism and exact beat operation boundaries before implementation. Recommendation pending user agreement: explicit trusted grant/revoke command by stable user ID, with ordinary-user defaults.
- Run relevant checks and the required Fallow audit; keep review, integration, and human acceptance separate.
