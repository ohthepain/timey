# One persistent issue conversation with isolated execution

The user approved one interactive conversation per issue across its lifecycle.
Keep human messages and role contributions together, with explicit provenance and
links to their original records. Implementation retains isolated checkouts and
review retains independent contexts, so conversational continuity does not give
one model both implementation and acceptance authority. Persist conversation
history locally and share selected-issue context with each role; explicit existing
handlers still own answers, approvals, integration and closure. This replaces the
issue screen's ephemeral discussion policy for new messages; expired temporary
conversations cannot be reconstructed.
